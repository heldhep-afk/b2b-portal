# B2B Портал

Платформа для оптовых поставок между компаниями: каталог товаров, заявки на покупку, согласование сделок, оплата через администратора платформы и независимая проверка качества силами проверяющих.

Написано на чистом PHP 8 без фреймворков и Composer-зависимостей: собственный роутер, контроллеры, шаблоны-представления и PDO для доступа к MySQL. Интерфейс — Bootstrap 5 с собственной темой в стиле Apple.

---

## Что делает приложение

Портал заменяет переписку и ручные таблицы при оптовых закупках:

- **Каталог** — компании выставляют товары с ценой, минимальной партией, складским остатком и описанием. Покупатель ищет и фильтрует предложения.
- **Заявка** — покупатель собирает несколько товаров от разных продавцов в одну корзину; суммы пересчитываются по каждому продавцу.
- **Сделка** — при оформлении создаётся отдельная сделка с каждым продавцом. Покупатель одобряет или отклоняет её, администратор платформы подтверждает оплату, завершает сделку и выплачивает деньги продавцу.
- **Проверка качества** — покупатель может заказать независимую проверку товара перед сделкой. Проверяющий берёт задачу, выезжает на место (или проверяет удалённо), публикует отчёт с вердиктом и ссылками.
- **Команда** — у компании есть сотрудники с ролями и настраиваемыми правами; один человек может работать от имени нескольких связанных компаний.
- **Администрирование** — панель платформы: этапы сделок, персонал, заявки проверяющих, статистика по дням и месяцам.

## Роли и участники

| Роль | Что может |
|------|-----------|
| **Гость** | Смотрит каталог и карточки компаний, регистрируется, входит, подаёт заявку «Стать проверяющим», присоединяется к компании по коду. |
| **Покупатель** (`role = client`) | Собирает заявку, оформляет сделки, одобряет/отклоняет их, заказывает проверку, оплачивает через администратора. |
| **Продавец** | Та же учётная запись компании; видит входящие сделки, подтверждает заказ, управляет своими товарами. |
| **Директор компании** (`company_role = owner`) | Всё, что может компания, плюс управление командой, ролями и правами. |
| **Менеджер** (`company_role = manager`) | По умолчанию: закупки, решения по сделкам, товары, категории, заявки на вступление. |
| **Сотрудник** (`company_role = employee`) | По умолчанию только закупки; остальные права включаются точечно. |
| **Проверяющий** (`role = inspector`) | Отдельный кабинет: пул задач, взятие задачи, согласование визита, отчёт с вердиктом. |
| **Администратор** (`role = admin`) | Панель платформы: сделки по этапам, оплата, выплаты, возвраты, персонал, проверки, статистика. |

Права внутри компании: `create_deals`, `decide_deals`, `manage_products`, `manage_categories`, `edit_company`, `review_requests`; управление командой доступно только директору. Права можно переопределять индивидуально — в матрице на странице `/team`.

## Пользовательские сценарии

### Покупатель: от каталога до сделки

1. Регистрирует компанию на `/register` (становится её директором) или входит по email.
2. Ищет товары в каталоге: категории, цена, продавец, сортировка, персональные рекомендации.
3. Добавляет позиции в заявку `/cart`, указывает количество (не меньше минимальной партии).
4. На `/checkout` проверяет состав, адрес доставки и комментарий; при желании включает проверку качества.
5. Оформляет заявку — создаётся по одной сделке на каждого продавца.
6. В `/account` одобряет сделку или отклоняет её; после оплаты администратором сделка завершается.
7. Повторяет закупку одной кнопкой: все позиции прошлой сделки снова попадают в заявку.

### Продавец

1. Ведёт карточки товаров в `/company`: название, цена, единица, минимальная партия, остаток, категория, артикул, описание.
2. Видит входящие сделки в своём кабинете; после подтверждения оплаты администратором сделка переходит в работу.
3. Следит за статусом оплаты и выплаты, видит историю событий по сделке.

### Команда компании

1. Директор открывает `/team`, копирует код компании или отключает приём заявок.
2. Новый сотрудник вводит код на `/join`; заявка попадает директору.
3. Директор одобряет или отклоняет заявку, назначает роль и права.
4. Сотрудник со статусом `pending` видит страницу ожидания `/pending` и не может совершать действия.
5. Один пользователь может привязать несколько компаний (`/account/link`) и переключаться между ними в шапке.

### Проверка качества

1. Покупатель в сделке нажимает «Заказать проверку», выбирает дату/время визита и оставляет пожелания.
2. Администратор подтверждает оплату проверки и назначает проверяющего (или задача попадает в общий пул).
3. Проверяющий берёт задачу, согласует визит с продавцом, при необходимости переносит время.
4. После проверки публикует отчёт: вердикт (`ok` / `remarks` / `fail`), краткое резюме, детали, ссылки на материалы.
5. Администратор утверждает отчёт; проверка блокирует завершение сделки, пока не будет утверждена или отменена.

### Администратор платформы

- `/admin` — сделки, сгруппированные по этапам: **оплата → подтверждение → выплата → возврат**.
- Действия: подтвердить оплату, завершить сделку, отменить, выплатить продавцу, вернуть деньги покупателю.
- `/admin/staff` — персонал платформы и заявки «Стать проверяющим».
- `/admin/inspections` — проверки: подтверждение оплаты, назначение проверяющего, утверждение/возврат отчёта, отмена.
- `/admin/stats` — оборот, количество сделок, средний чек, график по месяцам/дням и календарь активности.

### Аккаунт и доступ

- Вход и регистрация с валидацией на клиенте и сервере.
- Восстановление пароля по одноразовой ссылке из письма (действует 1 час).
- Профиль `/profile`: имя, должность, телефон, данные компании, пароль.
- Тема оформления: авто / светлая / тёмная, выбор запоминается в браузере.

## Статусы

**Сделка** (`deals.status`)

| Статус | Значение |
|--------|----------|
| `in_progress` | В работе: создана, ожидает оплаты/подтверждения |
| `completed` | Завершена |
| `rejected` | Отклонена покупателем |
| `cancelled` | Отменена администратором |

**Оплата** (`deals.payment_status`)

| Статус | Значение |
|--------|----------|
| `unpaid` | Не оплачена |
| `paid` | Оплачена, деньги у платформы |
| `paid_out` | Выплачена продавцу |
| `refunded` | Возвращена покупателю |

**Проверка** (`inspections.status`)

| Статус | Значение |
|--------|----------|
| `requested` | Заявка создана, проверяющий не назначен |
| `assigned` | Проверяющий назначен |
| `submitted` | Отчёт отправлен на утверждение |
| `approved` | Проверка утверждена |
| `cancelled` | Отменена |

Вердикт: `ok` — соответствует, `remarks` — есть замечания, `fail` — не соответствует.

## Модель данных

| Таблица | Назначение |
|---------|------------|
| `companies` | Компании: реквизиты, код вступления, приём заявок |
| `users` | Пользователи: роль на платформе, роль в компании, права, статус заявки |
| `user_links` | Связь пользователя с дополнительными компаниями |
| `categories`, `company_categories` | Категории товаров и интересы компаний |
| `products` | Товары: цена, единица, минимальная партия, остаток |
| `deals` | Сделки: покупатель, продавец, суммы, статусы, оплата |
| `deal_items` | Позиции сделки на момент оформления (название, артикул, количество, цена) |
| `deal_events` | История действий администратора по сделке |
| `inspections` | Проверки: оплата, проверяющий, визит, отчёт, вердикт |
| `inspection_events` | История проверки |
| `inspector_applications` | Заявки на роль проверяющего |
| `password_resets` | Одноразовые токены сброса пароля (хранится SHA-256) |

Колонки `deals.product_id`, `deals.quantity`, `deals.unit_price` сохранены для обратной совместимости и содержат первую позицию сделки; источник истины по составу — `deal_items`.

## Дизайн-система

- **Палитра**: бордовый бренд `#92223b` (в тёмной теме `#c2405d`), тёплый фон `#faf6f7`, тёмный фон `#141011`.
- **Типографика**: системный стек Apple/SF, крупные заголовки, табличные цифры для сумм.
- **Компоненты**: карточки с мягкими тенями, скругления 12–28 px, пилюли-бейджи, тумблеры, матрица прав, шаги-степперы, графики и календарь активности.
- **Тёмная тема**: отдельные переменные `--ap-*`, переопределения для таблиц, форм, меню, графиков и календаря; переключатель в шапке (авто/светлая/тёмная).
- **Адаптивность**: контрольные точки Bootstrap 5; таблицы прокручиваются по горизонтали, кнопки действий переносятся, длинные названия и ссылки не вылезают за карточки.
- **Доступность**: skip-link, подписи у полей, `aria-label` у иконочных кнопок, видимый фокус, контраст текста не ниже 4.5:1 в обеих темах, поддержка клавиатуры.

## Безопасность

- Пароли — `password_hash()` (bcrypt), проверка через `password_verify()`, автообновление устаревших хешей.
- Защита от подбора пароля: лимиты по email и по IP, счётчики в файлах вне веб-корня.
- Восстановление пароля: случайный токен (32 байта), в базе хранится только SHA-256, срок 1 час, одноразовое использование, отдельные лимиты на IP и email. Ответ одинаковый для существующего и несуществующего адреса.
- CSRF-токены на всех POST-формах с серверной проверкой.
- Все запросы к базе — подготовленные выражения (PDO), весь вывод экранируется через `htmlspecialchars()`.
- Цены, наличие и продавец в заявке всегда перечитываются из базы: подмена сессии не меняет сумму сделки.
- Cookie сессии: `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS; тайм-аут бездействия и периодическая смена ID сессии.
- Заголовки: CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Ошибки PHP не показываются посетителям, пишутся только в лог сервера.
- `config/`, `app/` и `views/` лежат вне веб-корня; `.htaccess` запрещает отдачу служебных и скрытых файлов.

## Установка

1. Скопируйте проект и создайте конфигурацию базы:

   ```bash
   cp config/db.example.php config/db.php
   ```

   В `config/db.php` укажите `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS` (или задайте одноимённые переменные окружения).

   Для писем о восстановлении пароля скопируйте `config/mail.example.php` в `config/mail.php` и укажите адрес отправителя и адрес сайта:

   ```bash
   cp config/mail.example.php config/mail.php
   ```

2. Создайте базу и импортируйте схему:

   ```bash
   mysql -u root -p -e "CREATE DATABASE b2b_portal CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
   mysql -u root -p b2b_portal < sql/schema.sql
   ```

   Если база уже развёрнута, примените миграции из `sql/migrations/` — они идемпотентны:

   ```bash
   mysql -u root -p b2b_portal < sql/migrations/2026-11-01-deal-items-password-resets.sql
   ```

   Миграция создаёт таблицы `deal_items` и `password_resets` и переносит существующие сделки в позиции.

3. Направьте корень сайта на каталог `public_html`, остальные каталоги должны остаться недоступными из веба.

4. Создайте первого администратора платформы — запись в `users` с `role = 'admin'` и паролем из `password_hash()`:

   ```bash
   php -r "echo password_hash('ваш-пароль', PASSWORD_DEFAULT), PHP_EOL;"
   ```

   ```sql
   INSERT INTO companies (name, inn) VALUES ('Платформа', '0000000000');
   INSERT INTO users (company_id, username, email, password_hash, role, company_role, is_active, join_status)
   VALUES (1, 'admin', 'admin@example.com', '<хеш из команды выше>', 'admin', 'owner', 1, 'approved');
   ```

5. Откройте сайт: `/` — каталог, `/login` — вход, `/admin` — панель администратора.

Для отладки подключения к базе задайте `APP_DEBUG=1` — страница ошибки покажет хост и имя базы.

### Развёртывание

- Каталог `storage/` должен быть доступен на запись веб-серверу (там лежат счётчики лимитов).
- Включите HTTPS: cookie сессии станут `Secure` автоматически.
- Проверьте, что `config/db.php` и `config/mail.php` не попали в репозиторий и недоступны по HTTP.
- После обновления файлов очистите кэш браузера или поднимите версию `theme.css?v=` в `views/layout/header.php`.

## Структура

```
app/
  Controllers/   обработчики маршрутов (компании, сделки, админка, проверки)
  Core/          роутер, хелперы, права доступа, лимиты, корзина, рекомендации, почта
config/
  db.example.php шаблон подключения к MySQL
  db.php         локальные доступы (не публикуется)
  mail.example.php шаблон настроек писем
  mail.php       адрес отправителя и URL сайта (не публикуется)
public_html/     единственный каталог, доступный из веба
  index.php      точка входа: сессия, заголовки, маршруты
  css/theme.css  тема оформления
  .htaccess      rewrite на index.php, запрет служебных файлов
sql/
  schema.sql     схема базы данных
  migrations/    миграции для уже развёрнутых баз
views/           шаблоны: каталог, заявка, кабинеты, админка
storage/         счётчики лимитов (создаётся автоматически)
```
